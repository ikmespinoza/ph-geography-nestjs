# Architecture Rules

- **Single standalone NestJS app — a modular monolith.** One deployable, one PostgreSQL, one Prisma schema. No microservices, no NATS, no per-service databases, no shared `libs/contracts`, no k8s fan-out.
- **Two internal module groups, one seam.** `geography/` (regions, provinces, cities, classifications) only **reads** the DB and serves the public API; `ingestion/` (scraper-core, source scrapers, change-detection, scheduler) only **writes** it. Keep that read/write split — it's the fault line if the service is ever decomposed. Shared plumbing lives in `common/`, `config/`, `persistence/`.
- **Controllers are the only HTTP surface.** Global prefix `api` + URI versioning (`/api/v1`). Every request body/query/param that carries structure gets a class-validator DTO; every route group appears in Swagger (`@nestjs/swagger`).
- **Layering: `controller → service → repository (Prisma)`.** Controllers are thin — validate input, call a service, shape output; no business logic or DB access in them. The DB is reached only through `PrismaService` (in `persistence/`). Inject providers — never `new` them.
- **Ingestion is in-process and scheduled.** `@nestjs/schedule` `@Cron` drives it; a guarded manual trigger (`pnpm ingest`, optional endpoint) runs it on demand. Fetch through one `HttpFetcher` (timeout / retry / User-Agent from config); parse with a `cheerio` `HtmlParser` using resilient selectors + row-shape validation; source logic implements the `GeoSource` interface. **Fail loudly on layout drift — never silently insert garbage.** Fetch only allow-listed source URLs.
- **Persistence is idempotent.** Ingestion writes are upserts keyed by a natural key (region/province `code`; city by `province + name`); seeds re-run cleanly. Change-detection skips a source page that hasn't advanced since last seen.
- **Config through `@nestjs/config` + a Zod schema** (fail-fast at boot). Never read `process.env` outside the config layer; no hardcoded URLs / secrets / timeouts.
- **Schema changes always ship a committed migration.** `pnpm prisma migrate dev --name <name>` (don't put `--` before the flags — pnpm passes it through and Prisma hangs). Migrations under `prisma/migrations/` are always committed, in the **same change-set** as the model change; never edit a migration after it's merged — write a follow-up.
- **The legacy Laravel/Lumen API is read-only reference** for parity only — never port PHP idioms verbatim.
